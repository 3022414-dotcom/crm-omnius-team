## 2. Цель системы

Минимальная внутренняя CRM, которая вписывается в AI-first инфраструктуру команды: хранит данные по клиентам, контактам и сделкам, даёт наглядную картину воронки и легко интегрируется с AI-инструментами через экспорт в Markdown.

**Принципы:**
- Простота важнее полноты — никаких лишних полей на старте
- AI-совместимость — данные доступны в `.md` для Claude и других агентов
- Масштабируемость — архитектура позволяет добавлять новые сущности (Campaigns и др.) без переписывания

## 6. Notes — сквозные заметки

Notes — единая система заметок, привязанных к любой сущности (Account, Contact, Deal).

**Структура заметки:**
- Текст (textarea, без форматирования)
- Дата и время создания (автоматически)
- Автор (из списка пользователей, автоматически от авторизованного пользователя)
- Вложения (файлы / скриншоты — см. раздел 7)

**Сквозная видимость:**  
При просмотре карточки Account отображаются все Notes, оставленные в связанных Contacts и Deals. При просмотре Deal — все Notes связанных Contacts. **Это ключевое требование.**

---

## 7. Attachments — вложения

Вложения доступны в Notes, а также напрямую в карточках Account, Contact, Deal.

- Поддерживаемые форматы: изображения (PNG, JPG, GIF, WebP), документы (PDF, DOCX, XLSX, MD, TXT)
- Загрузка через drag-and-drop и через кнопку «Прикрепить»
- Вставка скриншота из буфера обмена (Ctrl+V в поле загрузки)
- Хранение: файлы хранятся на сервере, в БД — ссылка и метаданные (имя, размер, тип, дата, автор)
- Максимальный размер одного файла: 20 МБ

---

## 8. Activities — задачи и CTA

Activities привязаны к Deal и представляют собой простой список задач/следующих шагов.

**Структура активности:**
- Название / описание (string)
- Дедлайн (date)
- Статус: Open / Closed
- Исполнитель (список пользователей)
- Дата закрытия (автоматически при смене статуса на Closed)

*Интеграция с Google Calendar — бэклог.*

## 9. Канбан-доска

В MVP реализуется одна канбан-доска — по сущности Deal.

**Deals Kanban:**
- Колонки по стейджам: Lead → Qualifying → Discovery → Proposal → Closing → Contract → Won → Lost
- Карточка: Deal Name, Account, Amount, Deal Owner, Expected Start Date
- Перетаскивание между колонками (drag & drop) с автоматическим обновлением поля Stage
- Фильтрация: по Deal Owner, по Project Domain

*Канбан по Contacts (стейджи входящих кампаний: New → Outreach → Contact Made → Intro Call → Lost) — бэклог вместе с Campaigns.*

---

## 10. Файловая структура артефактов

Структура папок в Google Drive (ссылки хранятся в полях Account Storage и Deal Storage):

- Account (наименование клиента) → Account Storage
  - Deal 1 (Deal Name) → Deal Storage
    - 1.1.1 Initial info
    - 1.1.2 Proposal
    - 1.1.3 Contract
    - 1.1.4 Project
  - Deal 2...

CRM хранит только ссылки на папки. Сами файлы живут в Google Drive. Экспорт записей в `.md` происходит автоматически — для подключения Claude и других AI-инструментов.

## 12. Ограничения и исключения

Следующие категории клиентов и проектов не отражаются в CRM:
- Проекты в сфере military, gambling, dating, МФО, porno
- Клиенты с потребительским / токсичным отношением

**Технические ограничения MVP:**
- Мобильная версия — адаптивная вёрстка желательна, но не критична для MVP
- Офлайн-режим — не требуется
- Экспорт в Excel/CSV — бэклог
