**Created**: 2026-05-24

**Status**: Draft

**Input**: F-02 из all-features-mvp.md — вход только через Google OAuth 2.0, доступ только для pre-approved пользователей из таблицы users.

- Q: Входит ли UI страницы входа в scope F-02? → A: Да — минимальная server-rendered HTML-страница с кнопкой "Войти через Google" (без дизайна, только функциональность)

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Вход в систему (Priority: P1)

Участник команды открывает CRM, нажимает "Войти через Google", проходит стандартный OAuth-флоу и получает доступ к системе. Если его Google-аккаунт не зарегистрирован в системе — вход отклоняется с понятным сообщением.

**Why this priority**: Без рабочего входа система недоступна. Это единственный путь аутентификации.

**Independent Test**: Открыть страницу входа, нажать кнопку, пройти Google OAuth → попасть в CRM (для зарегистрированного пользователя) или получить сообщение об отказе (для незарегистрированного).

**Acceptance Scenarios**:

1. **Given** пользователь существует в таблице users (email совпадает), **When** нажимает "Войти через Google" и проходит OAuth, **Then** сессия создаётся, пользователь перенаправляется на главную страницу CRM
2. **Given** Google-аккаунт не добавлен в таблицу users, **When** пользователь проходит OAuth с незарегистрированным аккаунтом, **Then** вход отклонён, отображается сообщение "Доступ запрещён. Обратитесь к администратору."
3. **Given** Google возвращает email без подтверждения (`email_verified: false`), **When** пользователь проходит OAuth, **Then** вход отклонён с соответствующей ошибкой
4. **Given** пользователь не авторизован, **When** обращается к любому защищённому маршруту `/api/v1/*`, **Then** возвращается ответ 401 Unauthorized

---

### User Story 2 — Выход из системы (Priority: P2)

Авторизованный пользователь завершает сессию нажатием кнопки "Выйти". Система уничтожает сессию и возвращает пользователя на страницу входа.

**Why this priority**: Безопасный выход — обязательное требование для любой системы с авторизацией.

**Independent Test**: Войти в систему → нажать "Выйти" → попытаться обратиться к защищённому маршруту → получить 401.

**Acceptance Scenarios**:

1. **Given** пользователь авторизован, **When** нажимает "Выйти", **Then** сессия уничтожается, пользователь перенаправляется на страницу входа
2. **Given** пользователь вышел из системы, **When** обращается к защищённому маршруту, **Then** возвращается 401

---

### User Story 3 — Сохранение сессии между перезапусками (Priority: P3)

Пользователь остаётся авторизованным после перезапуска сервера. Сессии хранятся в базе данных, а не в памяти процесса.

**Why this priority**: Критично для production-использования — перезапуск сервера не должен разлогинивать всех пользователей.

**Independent Test**: Войти в систему → перезапустить сервер → обратиться к защищённому маршруту → получить успешный ответ без повторного входа.

**Acceptance Scenarios**:

1. **Given** пользователь авторизован, **When** сервер перезапускается, **Then** сессия сохраняется, пользователь остаётся авторизованным
2. **Given** активная сессия существует в базе данных, **When** происходит перезапуск, **Then** при следующем запросе сессия восстанавливается из БД автоматически

---

### Edge Cases

- Что происходит, если Google возвращает email без подтверждения (`email_verified: false`)? → Вход отклоняется, пользователь получает понятное сообщение.
- Что происходит, если пользователь удалён из таблицы users при наличии активной сессии? → При следующем запросе к защищённому маршруту сессия инвалидируется и пользователь перенаправляется на страницу входа.
- Что происходит при попытке OAuth без настроенных Google credentials? → Сервер отказывается стартовать с понятным сообщением об ошибке конфигурации.
- Что происходит при одновременном входе одного пользователя с нескольких устройств? → Каждое устройство получает отдельную сессию, обе активны.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST аутентифицировать пользователей исключительно через Google OAuth 2.0 — никакого входа по паролю или другим провайдерам
- **FR-010**: Система MUST предоставлять минимальную server-rendered HTML-страницу входа с кнопкой "Войти через Google" (без дизайна, только функциональность)
- **FR-002**: Система MUST проверять наличие Google-аккаунта (по email) в таблице pre-approved пользователей перед созданием сессии
- **FR-003**: Система MUST отображать понятное сообщение "Доступ запрещён. Обратитесь к администратору." при попытке входа незарегистрированного пользователя
- **FR-004**: Система MUST защищать все маршруты `/api/v1/*`, возвращая 401 для неавторизованных запросов
- **FR-005**: Система MUST хранить сессии в PostgreSQL (таблица session, созданная в F-01)
- **FR-006**: Система MUST предоставлять маршрут выхода, уничтожающий сессию на сервере
- **FR-007**: Система MUST сохранять Google-идентификатор (`google_id`) пользователя в таблицу users при первом успешном входе
- **FR-008**: Система MUST отклонять вход, если Google возвращает email с `email_verified: false`
- **FR-009**: Система MUST инвалидировать сессию пользователя при следующем запросе, если пользователь удалён из таблицы users

### Key Entities

- **Session**: Контекст аутентифицированного пользователя; хранится в PostgreSQL; содержит идентификатор пользователя и время истечения (TTL: 7 дней); переживает перезапуск сервера
- **User (существующий)**: Pre-approved участник команды; идентифицируется по email; при первом входе записывается Google-идентификатор

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Зарегистрированный участник команды проходит полный цикл входа (от нажатия кнопки до доступа к CRM) менее чем за 5 секунд
- **SC-002**: 100% запросов к защищённым маршрутам от неавторизованных пользователей получают ответ 401
- **SC-003**: 100% попыток входа с незарегистрированных Google-аккаунтов отклоняются с понятным сообщением об ошибке
- **SC-004**: Активные сессии пользователей сохраняются после перезапуска сервера (нулевая потеря сессий); сессия автоматически истекает через 7 дней неактивности
- **SC-005**: Выход из системы завершается и инвалидирует сессию в течение 1 секунды

## Assumptions

- Единственный метод входа — Google OAuth 2.0; никаких email/пароль или других провайдеров
- 4 участника команды уже pre-seeded в таблице users (из F-01); самостоятельная регистрация невозможна
- Добавление новых пользователей — задача администратора (вне scope F-02, рассматривается в F-03+)
- В production сервер работает по HTTPS (для secure cookies); в development — HTTP
- Google OAuth credentials (CLIENT_ID, CLIENT_SECRET) настраиваются через переменные окружения
- Зависит от F-01: таблицы users и session уже созданы и доступны
- Страница входа — server-rendered HTML (без фронтенд-фреймворка); дизайн и интеграция с React/Next.js — в F-11
