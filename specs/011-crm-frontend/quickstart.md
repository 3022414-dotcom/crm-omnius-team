# Quickstart: Фронтенд CRM

**Branch**: `011-crm-frontend` | **Date**: 2026-07-05

## Предварительные требования

- Node.js LTS установлен
- Backend запущен на `localhost:3000` (либо `npm start` локально или `docker-compose up -d`)
- `.env` в корне проекта содержит `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SESSION_SECRET`
- Добавить в `.env`: `FRONTEND_URL=http://localhost:5173`

---

## 1. Установка и первый запуск

```bash
# Установить зависимости frontend
cd client
npm install

# Запустить dev-сервер (Vite на порту 5173)
npm run dev
```

Открыть `http://localhost:5173` → должна отображаться страница входа с кнопкой «Войти через Google».

---

## 2. Проверка авторизации

```bash
# Проверить текущую сессию через API
curl -s http://localhost:3000/api/v1/users/me
# → {"error":"Unauthorized"} — корректно, сессии нет

# Войти через браузер: http://localhost:5173 → «Войти через Google»
# После успешного OAuth: должен попасть на главный экран CRM
```

**Ожидаемое**: после входа браузер редиректит на `http://localhost:5173/`, отображается AppShell с навигацией.

---

## 3. Тема (light/dark)

1. Нажать кнопку переключения темы в шапке
2. Страница переключается без перезагрузки
3. Обновить вкладку → тема сохранилась
4. Открыть DevTools → `localStorage.getItem('theme')` → `"dark"` или `"light"`

---

## 4. Навигация

| Раздел | URL | Ожидаемое |
|--------|-----|-----------|
| Аккаунты | `/accounts` | Таблица аккаунтов с поиском |
| Контакты | `/contacts` | Таблица контактов с поиском |
| Сделки | `/deals` | Таблица сделок с фильтрами |
| Kanban | `/kanban` | 6 колонок с карточками сделок |
| Активности | `/activities` | Список активностей с фильтрами |

---

## 5. CRUD — аккаунты (admin/bdm)

```
# В браузере (залогиненный admin/bdm):
1. Перейти на /accounts
2. Нажать «Создать аккаунт» → открылся модал
3. Заполнить название → Сохранить
4. Аккаунт появился в списке без перезагрузки
5. Кликнуть на аккаунт → детальная страница с вкладками
6. Вкладка «Заметки» → добавить заметку → заметка появилась
7. Вкладка «Вложения» → загрузить файл → файл появился
8. Нажать «Удалить» → диалог подтверждения → аккаунт удалён
```

## 6. Kanban drag-and-drop

```
# В браузере (залогиненный admin/bdm):
1. Перейти на /kanban
2. Убедиться что видны 6 колонок (в т.ч. пустые)
3. Перетащить карточку из колонки «lead» в «qualified»
4. Обновить страницу → карточка осталась в «qualified»

# Проверить через API:
curl -s http://localhost:3000/api/v1/deals/kanban \
  -H "Cookie: connect.sid=..." | jq '.qualified | length'
```

## 8. Глобальная страница активностей

```
# admin — видит все активности
GET /api/v1/activities
→ все активности команды

# admin — фильтр по пользователю
GET /api/v1/activities?owner_id=<uuid_anastasia>
→ только активности Анастасии

# bdm — только свои
GET /api/v1/activities
→ только активности текущего bdm (owner_id автоматически = req.user.id)

# В браузере: /activities → список с фильтрами по статусу и типу
# Просроченные (overdue=true) выделены красным
```

## 9. Production build

```bash
cd client
npm run build
# Собирается в client/dist/

# Запустить Express в production-режиме
NODE_ENV=production npm start
# Открыть http://localhost:3000 → должна открыться CRM (SPA из client/dist)
```
