# Implementation Plan: Entity Detail Page Redesign

**Branch**: `013-entity-detail-redesign` | **Date**: 2026-07-10 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/013-entity-detail-redesign/spec.md`

## Summary

Redesign detail views for Account, Contact, and Deal entities. Each gets a dedicated route (`/accounts/:id`, `/contacts/:id`, `/deals/:id`) with a two-panel layout: left panel (~340px fixed) displays all entity fields as inline-editable components; right panel (flex-1) shows tabs for related entities. Contact detail adds avatar display and photo upload/delete UI (backend already implemented). All field labels are in English. The existing modal Edit button is removed from all three entity types; inline editing becomes the sole edit mechanism. No backend changes required.

## Phases

### Phase 1: Shared Infrastructure

**Goal**: Create reusable components and verify routing before any entity-specific work.

**Tasks**:
1. Create `DetailLayout.jsx` — two-panel CSS Grid wrapper (left 340px fixed, right flex-1, both panels scrollable)
2. Create `InlineField.jsx` — universal inline-edit component supporting text, select, date, textarea, url, email, toggle types
3. Create `InlineMultiSelect.jsx` — checkbox dropdown for array fields (Our Services on Deal)
4. Create `ContactAvatar.jsx` — avatar display, file picker trigger, upload/delete logic
5. Verify API functions exist: `getAccountById`, `updateAccount`, `getContactById`, `updateContact`, `getDealById`, `updateDeal`, `uploadContactPhoto`, `deleteContactPhoto` — create any missing ones in `client/src/api/`

**Exit criteria**: Components render in isolation (can test by temporarily mounting in any existing page).

---

### Phase 2: Account Detail Page

**Goal**: `/accounts/:id` route renders with full 2-column layout and all fields inline-editable.

**Tasks**:
1. Create `AccountDetailPage.jsx`:
   - Fetch account with `useQuery` (key: `['account', id]`)
   - Left panel: all 12 Account fields as `<InlineField>` components using Account Field Registry from data-model.md
   - Right panel: `<EntityTabs>` with Contacts, Deals, Notes, Attachments, Activities tabs (reuse existing tab content components)
   - Breadcrumb: `← Accounts` link back to `/accounts`
2. Add route in `AccountsPage.jsx`: `<Route path=":id" element={<AccountDetailPage />} />`
3. Modify `AccountsPage.jsx` list: clicking a row navigates to `/accounts/${id}` (replace side-panel open with `navigate`)
4. Remove "Edit" button / modal invocation from Account list view

**Exit criteria**: Open `/accounts/:id` → see 2-column layout; edit Industry field → saves; click Contacts tab → shows account's contacts.

---

### Phase 3: Contact Detail Page

**Goal**: `/contacts/:id` route renders with avatar, all fields inline-editable, photo upload works.

**Tasks**:
1. Create `ContactDetailPage.jsx`:
   - Fetch contact with `useQuery` (key: `['contact', id]`)
   - Left panel top: `<ContactAvatar>` component
   - Left panel body: all 16 Contact fields as `<InlineField>` using Contact Field Registry
   - Right panel: `<EntityTabs>` with Deals, Notes, Attachments, Activities tabs
   - Breadcrumb: `← Contacts`
2. Add route in `ContactsPage.jsx`: `<Route path=":id" element={<ContactDetailPage />} />`
3. Modify `ContactsPage.jsx` list: clicking navigates to `/contacts/${id}`
4. Remove "Edit" button / modal invocation from Contact list view
5. Wire `ContactAvatar` to `POST /api/v1/contacts/:id/photo` and `DELETE /api/v1/contacts/:id/photo`; invalidate `['contact', id]` query on success

**Exit criteria**: Open `/contacts/:id` → avatar shows; upload new photo → avatar updates; edit Position → saves; viewer sees read-only avatar (no upload controls).

---

### Phase 4: Deal Detail Page

**Goal**: `/deals/:id` route renders with all Deal fields inline-editable, conditional Lost Reason visible.

**Tasks**:
1. Create `DealDetailPage.jsx`:
   - Fetch deal with `useQuery` (key: `['deal', id]`)
   - Left panel: all Deal fields as `<InlineField>`, with Lost Reason conditionally rendered (visible only when `stage === 'lost'`)
   - Right panel: `<EntityTabs>` with Contacts (shows deal_contacts with role/comment), Notes, Attachments, Activities tabs
   - Breadcrumb: `← Deals`
2. Add route in `DealsPage.jsx`: `<Route path=":id" element={<DealDetailPage />} />`
3. Modify `DealsPage.jsx` list: clicking navigates to `/deals/${id}`
4. Remove "Edit" button / modal invocation from Deal list view
5. When Stage inline-saves to "lost": invalidate query (Lost Reason field appears because component re-renders with new data)

**Exit criteria**: Open `/deals/:id` → see all fields; change Stage to "lost" → Lost Reason appears; edit Title → saves; Contacts tab shows linked contacts with role.

---

### Phase 5: Polish & Cleanup

**Goal**: Consistent UX, edge cases covered, all 14 quickstart scenarios pass.

**Tasks**:
1. Verify empty-state messages in all tabs ("No contacts yet", "No notes yet", etc.)
2. Add client-side file size validation in `ContactAvatar` (reject >5MB before upload)
3. Add non-image file type validation (reject non JPEG/PNG/WebP)
4. Verify viewer role: set `readOnly={true}` on all `<InlineField>` components when `user.role === 'viewer'`; set `canEdit={false}` on `<ContactAvatar>`
5. Verify breadcrumb / Back navigation works from all three detail pages
6. Manual test all 14 quickstart scenarios; mark off in tasks.md
