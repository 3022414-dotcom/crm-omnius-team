# Quickstart: Entity Field Fixes — F-15

**Feature**: F-15 | **Branch**: `015-entity-fields-fix`

## Предварительные условия

1. Docker запущен, БД поднята: `docker compose up -d`
2. Миграция применена: `npm run migrate up` (server/)
3. Фронтенд и бэкенд запущены
4. В системе есть хотя бы одна сделка, один аккаунт, один контакт

---

## Сценарий 1: Our Services — корректные значения

1. Открыть карточку любой сделки
2. Кликнуть на поле **Our Services**
3. **Ожидаемо**: доступны ровно 7 вариантов — Workshop, Webinar, Consulting, POC, Development, Accelerator, Performance
4. **Не ожидаемо**: старые значения (AI Consulting, AI Outsource, AI Outstaff, AI Course, AI Product)
5. Выбрать несколько → сохранить → перезагрузить страницу → значения сохраняются

---

## Сценарий 2: Amount форматирование

1. В карточке сделки найти поле **Amount**
2. Установить значение `5000000` → сохранить
3. **Ожидаемо**: отображается `5 000 000` (без знака ₽, с пробелом как разделителем тысяч)
4. Проверить: Amount = 0 → отображается `0`. Amount пустой → пустое поле.
5. Открыть карточку Account → вкладка Deals → Value в таблице тоже без ₽

---

## Сценарий 3: Deal Owner — выпадающий список пользователей

1. В карточке сделки найти поле **Deal Owner** (между Storage URL и Created By)
2. Кликнуть на поле → **ожидаемо**: выпадающий список всех пользователей системы (4 человека)
3. Выбрать другого пользователя → сохранить
4. **Ожидаемо**: поле показывает выбранное имя. Перезагрузить → значение сохранено.
5. Проверить под ролью **bdm**: список пользователей доступен (не 403)

---

## Сценарий 4: Created By — в сделке

1. Создать новую сделку (залогиненным пользователем)
2. Открыть карточку созданной сделки
3. **Ожидаемо**: поле **Created By** содержит имя текущего пользователя (read-only)
4. Открыть старую сделку (до миграции): **Created By** отображает «—»
5. Убедиться, что поле нельзя редактировать

---

## Сценарий 5: Created Date — в сделке

1. Открыть карточку сделки
2. **Ожидаемо**: поле **Created Date** содержит дату создания сделки в формате ДД.ММ.ГГГГ (read-only)
3. Поле не кликабельно и не редактируется

---

## Сценарий 6: Порядок полей в Deal

1. Открыть карточку сделки
2. Визуально проверить порядок полей (сверху вниз):
   Deal Name → Stage → Account → Location → Deal Type → Source → Project Domain → Description → Our Services → Amount → Currency → Storage URL → Deal Owner → Created By → Created Date → Expected Start Date → Close Date → Lost Reason (только при stage=lost)
3. **Ожидаемо**: порядок точно соответствует ТЗ

---

## Сценарий 7: Created By — в Account

1. Создать новый Account
2. Открыть карточку созданного аккаунта
3. **Ожидаемо**: поле **Created By** содержит имя текущего пользователя (read-only)
4. Старый аккаунт (до миграции): поле **Created By** показывает «—»

---

## Сценарий 8: Created By — в Contact

1. Создать новый Contact
2. Открыть карточку контакта
3. **Ожидаемо**: поле **Created By** содержит имя текущего пользователя (read-only)
4. Старый контакт: поле **Created By** показывает «—»

## Edge Cases

| Кейс | Ожидаемое поведение |
|------|---------------------|
| Amount = NULL | Поле пустое, не «—» |
| Amount = 0 | Отображается `0` |
| Created By = NULL (старая запись) | Отображается «—» |
| Our Services = [] (пустой массив) | Поле пустое, нет ошибки |
| Deal Owner = NULL | Отображается «—», dropdown позволяет выбрать |
| Роль viewer | Все поля read-only, Created By и Created Date тоже (без курсора редактирования) |
| Роль bdm | GET /api/v1/users возвращает список (не 403) |
