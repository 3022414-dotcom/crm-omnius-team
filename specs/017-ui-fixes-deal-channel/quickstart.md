# Quickstart: UI Bug Fixes & Deal Channel Field — F-17

**Feature**: F-17 | **Branch**: `017-ui-fixes-deal-channel`

## Предварительные условия

1. Docker запущен, БД поднята: `docker compose up -d`
2. Миграция применена: `npm run migrate up` (из корня проекта)
3. Backend пересобран/перезапущен после изменений в `server/`: `docker compose up -d --build backend` (если запуск через Docker) — **важно**: этот проект уже сталкивался с ситуацией, когда контейнер работал на устаревшем образе после коммита (см. F-15 инцидент); не забыть пересобрать после `/speckit-implement`
4. Фронтенд запущен (`npm run dev:client` или эквивалент)
5. В системе есть хотя бы одна сделка, один аккаунт, один контакт (с фото и без)

---

## Сценарий 1: Редактирование гиперссылочного поля (Account Website)

1. Открыть карточку любого Account с заполненным полем **Website**
2. Кликнуть на текст значения (не на иконку) → **ожидаемо**: поле переходит в режим редактирования, новая вкладка не открывается
3. Изменить значение → сохранить (Enter или blur) → **ожидаемо**: новое значение сохранено и отображается как раньше
4. Перезагрузить страницу → значение сохранилось

## Сценарий 2: Открытие ссылки через иконку

1. На том же поле **Website** найти маленькую иконку "открыть в новой вкладке" рядом со значением
2. Кликнуть на иконку → **ожидаемо**: ссылка открывается в новой вкладке, карточка НЕ переходит в режим редактирования

## Сценарий 3: То же самое на остальных полях-ссылках

Повторить сценарии 1–2 для:
- Account → Storage URL
- Deal → Storage URL
- Deal → Deal Channel (см. Сценарий 6)
- Contact → LinkedIn
- Contact → Facebook

**Ожидаемо**: везде одинаковое поведение (клик по тексту — редактирование, клик по иконке — открытие)

## Сценарий 4: Read-only (роль viewer)

1. Залогиниться пользователем с ролью **viewer**
2. Открыть любую карточку с полем-ссылкой
3. **Ожидаемо**: клик в любом месте поля (текст или иконка) только открывает ссылку; режим редактирования недоступен

## Сценарий 5: Пустое поле-ссылка

1. Открыть карточку с пустым полем-ссылкой (например, Contact без LinkedIn)
2. Кликнуть на поле → **ожидаемо**: переход в режим редактирования, как у любого другого пустого поля

## Сценарий 6: Deal Channel — новое поле

1. Открыть карточку любой сделки
2. **Ожидаемо**: поле **Deal Channel** расположено сразу после **Storage URL**
3. Ввести ссылку (например, `https://t.me/some_channel`) → сохранить
4. Перезагрузить страницу → значение сохранилось, отображается как кликабельная ссылка (текст + иконка открытия)
5. Оставить поле пустым при сохранении сделки → **ожидаемо**: ошибки нет, сделка сохраняется

## Сценарий 7: Deal Channel — форма создания/редактирования

1. Открыть модалку создания новой сделки (или редактирования через форму, если есть отдельная кнопка)
2. **Ожидаемо**: поле **Deal Channel** присутствует в форме, сразу после **Storage URL**
3. Заполнить и сохранить → значение появляется в карточке сделки после сохранения

## Сценарий 8: Полноразмерное фото контакта

1. Открыть карточку контакта с загруженным фото
2. Навести курсор на фото → **ожидаемо**: визуальный намёк, что фото можно открыть крупнее (помимо существующей иконки камеры для загрузки)
3. Кликнуть на фото → **ожидаемо**: открывается модальное окно с фото на весь размер поверх карточки
4. Нажать Escape ИЛИ кликнуть вне изображения → **ожидаемо**: модалка закрывается, карточка не изменилась
5. Открыть контакта БЕЗ фото → клик по области фото не пытается открыть полноразмерный просмотр (либо открывает загрузку фото для тех, у кого есть права редактирования — как и раньше)

## Сценарий 9: Загрузка нового фото по-прежнему работает

1. На карточке контакта с правами редактирования навести на фото → появляется иконка камеры (как раньше)
2. Кликнуть на иконку камеры → **ожидаемо**: открывается диалог выбора файла (загрузка нового фото), а не полноразмерный просмотр
3. Загрузить новое фото → сохраняется как раньше

---

## Сценарий 10: Расширяемое поле заметок

1. Открыть вкладку **Notes** любой сущности (Account/Contact/Deal)
2. Начать вводить текст заметки, добавляя новые строки (Enter) — **ожидаемо**: поле ввода плавно увеличивается по высоте вместе с текстом
3. Продолжить вводить текст до ~10 строк (~240px) → **ожидаемо**: дальнейший рост высоты останавливается, появляется внутренний скролл
4. Сохранить заметку → она сохраняется целиком (без обрезки), независимо от длины
5. Открыть существующую длинную заметку на редактирование → **ожидаемо**: поле сразу открывается растянутым под контент (в пределах максимума ~240px)

## Edge Cases

| Кейс | Ожидаемое поведение |
|------|---------------------|
| Ссылка без `https://` в поле (например, `example.com`) | Редактирование работает как обычно; иконка открытия использует значение как есть (браузер сам решает, как открыть) |
| Узкий экран / мобильный вид | Иконка "открыть" остаётся отдельным, надёжно кликабельным элементом, не сливается с текстом |
| Роль viewer + поле-ссылка | Только открытие по клику в любом месте поля, редактирования нет |
| Deal Channel = NULL (старая сделка) | Поле пустое, не «—» — так же, как Storage URL |
| Битое фото контакта (404 у файла) | Полноразмерный просмотр не пытается открыться / закрывается без ошибки |
| Escape при открытой модалке фото | Модалка закрывается |
| Очень длинная заметка (сильно больше 10 строк) | Поле не растёт бесконечно, скроллится внутри, сохранение не блокируется |
